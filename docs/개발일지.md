## 결정과 이유

- **네이버 예약 슬롯을 자동으로 가져오지 않습니다.** 원본 기획서 12~14장 스스로 「날짜·시간별 잔여 슬롯을 외부에서 가져올 수 있는지가 선행 게이트」이고 「비공식 내부 호출은 장기 운영에 부적합」이라고 결론냈습니다. 화면 긁어오기(스크래핑)·비공식 호출은 이용약관 위반·차단 위험이 있어 쓰지 않고, 1단계는 **사용자가 네이버 예약 페이지에서 확인한 값을 입력**하는 방식(원본 14장 「사용자 예약 페이지 확인 = 보조 방식」)으로 만들었습니다. 연계 확인은 「네이버 연계 준비」 화면과 기획서 8장 2단계 체크리스트로 남겼습니다.
- **판정 로직을 먼저 완성했습니다.** 원본 13장 ⑤ 연속시간 판정은 데이터를 어디서 받든 그대로 쓰므로 2단계에서도 재사용됩니다. 원본 5.2 표(10/01~10/04), 5.3 표(30분 ○○○○×), 5.4 표(T/S = 2·3·4·6)를 그대로 테스트로 옮겼습니다.
- **판정 규칙**
  - 필요 연속 슬롯 = T / S, 나누어떨어지지 않으면 올림(1.5시간 ÷ 1시간 슬롯 = 2개). 실제 판정은 「끊기지 않은 가능 슬롯 덩어리의 길이 ≥ T」로 해 코트마다 슬롯 단위가 달라도 같은 규칙으로 봅니다.
  - 희망 시간대 안에 **통째로 들어가는 슬롯만** 셉니다(21:30~22:30 은 22:00 까지 희망이면 빠짐).
  - 가능 시간을 적을 때 슬롯 하나를 다 채우지 못하는 자투리(30분 단위에서 19:00~19:15)는 예약 단위가 아니라 버립니다.
  - **자정을 넘는 시간대·슬롯은 1단계에서 받지 않고** 이유를 알려 줍니다. 날짜가 바뀌면 덩어리를 이어 붙이지 않습니다(10/01 23~24시 + 10/02 0~1시 ≠ 2시간).
- **「미입력」과 「확인했고 가능 없음」을 구분합니다.** 사용자가 손대지 않은 날은 「슬롯 미입력」으로 남겨 「네이버 예약 페이지에서 확인 필요」라고 보여 주고, 확인했는데 빈 시간이 없던 날은 「조건 미충족」으로 셉니다. 둘을 섞으면 확인하지 않은 코트가 「안 된다」로 보여 기회를 놓칩니다.
- **지도 대신 SVG 위치 그림**입니다. NAVER Maps 는 API 키와 서비스 URL 등록이 필요하고 공개 리포에 키를 둘 수 없습니다. 지도 타일도 외부 요청이라 넣지 않고, 기준점을 가운데 두고 방향·거리(평면 펼침, 반경 수십 km 안에서 오차 0.1% 이내)로 코트를 찍었습니다. 반경 원·절반 원·축척 막대·북쪽 표시를 넣었고, 「그림을 눌러 기준점 옮기기」를 켜면 누른 곳이 새 기준점이 됩니다(원본 3.1 「지도에서 위치 지정」의 대체).
- **Marker 상태는 원본 6장 기호**(● 조건 만족, ○ 미충족, × 네이버 예약 불가)에 「점선 ○ 슬롯 미입력」을 더했습니다. 색만으로 구분하지 않도록 모양이 다르고, 목록에 번호·상태 배지를 함께 둡니다.
- **목록 ↔ 표시 서로 강조**(원본 8장), 표시에 마우스 올림·키보드 초점 시 요약(원본 7장 Popup), 누르면 날짜별 상세(가능 시간·판정·시작 가능 시각)입니다.
- **예약 링크는 사용자가 넣은 URL 만**, 그것도 http·https 만 씁니다(javascript: 등 차단 — 로직·화면·DB CHECK 세 곳). URL 이 없으면 「네이버 지도에서 찾기」(이름+주소 검색 주소)를 대신 보여 줍니다. 사용자가 눌러 이동하는 일반 링크이며 API 호출이 아닙니다.
- **CSV 는 두 형식**을 받습니다. 원본 5.2 표처럼 「하루 한 줄 — 18:00~19:00, 20:00~22:00」과 원본 11.3 Availability 처럼 「슬롯 한 줄 — 시작·종료·가능 여부」. 엑셀에서 저장한 EUC-KR CSV 도 읽고, 내보낼 때 수식으로 읽힐 칸은 막습니다.
- **예시 데이터 URL 은 비웠습니다.** 가상 코트가 실제 예약 페이지로 연결되는 착각을 막기 위함입니다.
- **스크립트는 ES module 이 아닌 일반 스크립트**입니다. `index.html` 을 파일로 열면(file://) 브라우저가 module 스크립트를 막기 때문입니다. 외부 라이브러리는 쓰지 않았습니다.

## 가정

- 한 코트(시설)의 예약 가능 여부를 코트 단위로 봅니다. 면이 여러 개면 「어느 면이든 비어 있으면 가능」으로 입력한다고 가정했습니다(기획서 10장 2번).
- 최소 연속 이용시간은 1~4시간, 30분 간격(원본 5.4 「1~4시간 등으로 설정」). 희망 시간 선택은 30분 간격입니다.
- 한 번에 조회하는 기간은 최대 62일로 제한했습니다.
- 예시 기준점은 판교역 부근 어림 좌표(원본 16장 시나리오)이고, 예시 코트 위치·이름·주소·전화번호·슬롯은 모두 가상입니다.
